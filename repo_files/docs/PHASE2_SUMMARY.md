# Phase 2 Summary — Dataset pipeline and ML backend

> **Simulated target.** `Will_Attend` was generated by a documented probability model, so every number below measures recovery of the simulation rules. None of them establishes real-world attendance prediction performance.

## 1. What was implemented

| Area | Implementation |
|---|---|
| **Original data protection** | Workbook archived unchanged into `data/original/` (SHA-256 verified, file set read-only). The archive refuses to overwrite a differing file. Only `ML_Dataset` is read. `Raw_Merged_Data` is blocked even when requested by name. Uploads with personal-data columns are rejected |
| **Schema** | `core/schema.py` declares all 24 columns: type, allowed values, range, level (student/event/registration) and a pre-event flag. An assertion guarantees every model input is pre-event |
| **Validation** | `core/data_validation.py`: required columns, numeric/binary/category checks, ranges, missing values, duplicate rows, repeated Student+Event registrations, logical contradictions, single-class targets, class balance. Training and prediction modes. Never mutates its input |
| **Weather forecast** | `Weather` → `Weather_Forecast`. A blank becomes the explicit `Unavailable` category, never a guessed value. Provenance (forecast time unknown for original rows) is recorded in metadata |
| **Processed dataset** | `data/processed/ml_dataset_processed.csv` + metadata. Blanks are filled only from the same student's or same event's other rows, without using the target (59 cells). The other 37 blank cells are imputed inside the pipeline from training rows only |
| **Synthetic dataset** | `core/synthetic.py` re-implements Generation_Log §5–10: 783 registrations, 600 students, 48 events, seed 2026, `SYN-` IDs, `Data_Source = SYNTHETIC`, 8% of events without a forecast. Kept in `data/synthetic/` only |
| **Pipelines** | (a) A faithful replica of the original notebook as the baseline. (b) An EventPulse pipeline: Department, interest/role match, registration window, log counts, ordinal Experience_Level, median/most-frequent imputation, one-hot encoding (unseen categories ignored), scaling where needed |
| **Evaluation protocol** | One **student-grouped, stratified 20% holdout**: 306 train rows (222 students) and 77 holdout rows (57 students), with **0 students in both**. Hyper-parameters are tuned by **GridSearchCV with 5-fold StratifiedGroupKFold** on training rows only. The threshold is chosen from **out-of-fold training predictions** (maximum balanced accuracy). The recommended model is the **highest mean CV ROC-AUC**; the holdout is never used for selection. Every result sits beside the **majority-class baseline** |
| **Split sensitivity** | Each model's holdout AUC is re-measured on 10 different student-grouped splits and reported as a range. The summary warns automatically when the single holdout is unusually easy or hard |
| **Persistence** | `models/<model_id>/model.joblib` + `metadata.json` (inputs, parameters, threshold, CV and holdout metrics, baseline, permutation importance, reference values, data hash, Python and scikit-learn versions). `comparison.json` covers all models; `active_model.json` names the active one. Models saved under a different scikit-learn version are refused |
| **Prediction** | `core/prediction.py`: individual prediction with a probability, a conservative certainty label (Uncertain / Moderate / Clear) and what-if factor explanations. Bulk prediction with validation, predicted and expected attendance, an approximate 95% range and per-event totals |

### How to read these numbers
1. **The realistic ranking quality is ROC-AUC ≈ 0.75–0.80**, from the CV column and the 10-split range. The seed-42 holdout is an easier-than-average split: every model's holdout AUC is more than 1 SD above its CV mean. The holdout column is shown for completeness and should not be quoted on its own.
2. **Random Forest and Gradient Boosting are within one CV standard deviation of the recommended model.** The data cannot reliably separate them. Logistic Regression is recommended on the pre-registered rule (highest CV AUC). It is also the most interpretable and has the lowest Brier score among the tuned models.
3. **Accuracy vs. the baseline.** Always guessing "attend" gives 68.8%. The recommended model reaches 80.5% on this holdout, but its CV accuracy at the default 0.5 threshold is 73.6%. The gain is real but modest.
4. **The threshold trades recall between classes.** Tuning for balanced accuracy (on training data) lifts recall for non-attenders from 0.54 (baseline replica, threshold 0.5) to 0.79, at the cost of more missed attenders. For head-count planning, use the **expected attendance** (the sum of probabilities), which does not depend on the threshold.
5. **Why the baseline replica scores 79.2% here, not 67.53%.** The split is different (student-grouped holdout instead of a random row split) and the processed data has same-entity repairs. Neither change uses test information.
6. **Most informative inputs** for the recommended model (permutation importance on the holdout, AUC drop): Participated_UBA_Event_Before 0.039, Has_Exam_Near_Event 0.022, Area_Of_Interest 0.019, Event_Type 0.018, Event_Popularity 0.014. These match terms of the documented simulation formula. The model recovered the built-in rules; this is not a discovery about students.
7. **Weather:** every model learned almost no weather effect from 383 rows (under 1 percentage point on mean probability), although the simulation gave rain a strong effect. A missing forecast therefore makes little difference to predictions. This is a sample-size limitation.
8. **Cross-check on synthetic data:** the recommended model scores ROC-AUC 0.83 on the 783 synthetic rows and predicts 553 attendees where 528 attended. That is consistent, but only because both datasets share the same simulation rules.

## 5. Remaining issues / notes for Phase 3
- **Environment:** the build and tests ran in Claude's workspace (Python 3.13, scikit-learn 1.9.1). They have **not** been run on your Mac yet. If your scikit-learn version differs, run `python scripts/train_models.py` once to regenerate the models.
- **Small data:** 77 holdout rows make every single-split metric noisy (±1.3 points of accuracy per prediction). The app will always show CV and split-range figures beside holdout figures.
- **Deployed model** = the evaluated model, fitted on the 306 training rows. An optional "refit on all data" can be added to the Model Laboratory, clearly labelled as having no remaining holdout.
