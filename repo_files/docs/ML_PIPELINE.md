# ML Pipeline and Serving Artifact Contract

## Scope

This document describes the end-term prediction model served by `app.py`. It is separate from the desktop model registry under `models/`. The desktop application remains unchanged by this serving-artifact repair.

> **Simulated target notice:** `Will_Attend` is generated from documented simulation rules. Model results measure recovery of those rules and must not be represented as performance on recorded real attendance.

## Training data

The serving model is trained only from `data/event_attendance.csv`:

- Source label: `SYNTHETIC`
- Rows: 1,323
- Students: 1,000
- Events: 60
- Target: `Will_Attend` (912 attend, 411 do not attend)
- Generator: `scripts/generate_synthetic.py --students 1000 --events 60 --seed 2026`
- SHA-256: `e7e624bbd7616d907b7b9491b10f98fa0a336ab725ac05d3f56fd8a3ccedca47`

This dataset is not mixed with the 383-row processed original-hybrid dataset or the 783-row synthetic demo dataset. The 383-row data is used only as a separately labelled external check after fitting, never for training or model selection.

## Pipeline

`train.py` loads and validates the dataset with `core.data_validation.validate`, canonicalises it with `core.preprocessing.prepare_frame`, and passes the ordered raw columns in `core.schema.MODEL_INPUTS` into a complete sklearn `Pipeline`.

The model receives these twenty raw, pre-event inputs in this exact order:

1. `Course`
2. `Year`
3. `Currently_UBA_Volunteer`
4. `Participated_UBA_Event_Before`
5. `Experience_Level`
6. `Area_Of_Interest`
7. `Role`
8. `Event_Type`
9. `Event_Day`
10. `Event_Time`
11. `Event_Duration_Hours`
12. `Registration_Days_Before`
13. `Previous_Event_Attendance`
14. `Previous_Events_Registered`
15. `Previous_Attendance_Rate`
16. `Academic_Engagement_Score`
17. `Event_Popularity`
18. `Distance_From_Venue_KM`
19. `Has_Exam_Near_Event`
20. `Weather_Forecast`

The pipeline performs stateless pre-event feature engineering (department, interest/role match, registration window and log-transformed counts), then training-fitted median/most-frequent imputation, ordinal encoding, one-hot encoding and, for logistic regression, scaling. IDs, target, data-source labels and personal identifiers are not features.

## Evaluation and model selection

The split is student-grouped: 20% holdout first, followed by five-fold `StratifiedGroupKFold` on the training partition. No student appears in both train and holdout. Threshold selection maximises balanced accuracy from out-of-fold training probabilities. The selection metric is mean CV ROC-AUC; the holdout is reporting-only.

The 16 November 2026 documented sweep completed nine MLflow runs across Logistic Regression, Decision Tree, Random Forest and Gradient Boosting. Logistic Regression with `C=0.3` was selected because it had the highest mean CV ROC-AUC, 0.8612 ± 0.0135. Its holdout ROC-AUC is 0.8741, accuracy 0.7992, balanced accuracy 0.8075 and threshold 0.72. The holdout contains 264 registrations from 196 students.

## Artifact contract

`train.py` is the only supported producer of the serving artifact:

```text
data/event_attendance.csv
  -> validation + sklearn Pipeline fit
  -> MLflow SQLite run in mlflow.db
  -> model/model.joblib
  -> model/metadata.json
  -> FastAPI lifespan loads Predictor(model/)
```

The required artifact directory is `model/`:

| File | Contract |
|---|---|
| `model/model.joblib` | A fitted sklearn `Pipeline` containing preprocessing and classifier together. It must expose `predict_proba`. |
| `model/metadata.json` | Generated by `core.model_registry.save_model`; includes `model_id`, name, algorithm, parameters, ordered `inputs`, reference values, threshold, training data identity/hash/count, evaluation, MLflow run ID, simulated-target notice, timestamps and Python/scikit-learn versions. |

At startup `core.model_registry.load_model` verifies the saved scikit-learn major/minor version before deserialising. `Predictor` then validates every request, applies canonical preprocessing, indexes the frame with `MODEL_INPUTS`, calculates probability with the serialized pipeline and applies the serialized threshold. There is no formula or random fallback path.

## Reproducible commands

```bash
.venv/bin/python train.py --sweep --experiment eventpulse-attendance
.venv/bin/python -m pytest -q tests/test_app.py
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

The MLflow UI can inspect the local run history with:

```bash
.venv/bin/mlflow ui --backend-store-uri sqlite:///mlflow.db
```

Do not manually copy a desktop `models/<model_id>` directory into `model/`; retrain/export through `train.py` so the pipeline, metadata, MLflow run ID and evaluation remain consistent.
